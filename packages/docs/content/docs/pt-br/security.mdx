# Segurança

O OpenChamber dá acesso à sua máquina e ao seu código, então proteja-o antes que qualquer pessoa além de você possa alcançá-lo. Esta página cobre a senha de UI, as passkeys e o que saber antes de expor o OpenChamber a uma rede.

## Definir uma senha de UI

Inicie o OpenChamber com uma senha e a UI do navegador a solicita:

```bash
openchamber --ui-password be-creative-here
```

Você também pode defini-la com a variável de ambiente `OPENCHAMBER_UI_PASSWORD` em vez de colocá-la na linha de comando. Após o login, o OpenChamber lembra o dispositivo por um tempo para que você não seja solicitado toda vez.

Sempre defina uma senha se a instância puder ser alcançada por outra pessoa — especialmente por um [túnel](/pt-br/tunnels/) ou pela internet pública.

## Passkeys

Uma vez definida uma senha, você pode adicionar passkeys (Face ID, Touch ID, uma chave de segurança) para um login mais rápido. Adicione-as em **Settings → OpenChamber → Passkeys**.

As passkeys estão vinculadas à senha atual. Se você alterar ou remover a senha, as passkeys salvas são apagadas e você precisará adicioná-las novamente.

## Tokens de dispositivo

Os dispositivos pareados por [Conectar um Dispositivo](/pt-br/connect-devices/) se autenticam com os próprios tokens por dispositivo, não com a senha de UI. Os links de pareamento são de uso único e expiram se não forem usados; cada dispositivo pareado é listado em **Settings → Remote Instances → Conectar a este servidor**, onde você pode revogar qualquer um deles a qualquer momento. As conexões fora de casa passam pelo [Private Relay](/pt-br/private-relay/), que é criptografado de ponta a ponta e não consegue ler o seu tráfego.

## Antes de expô-lo

- Por padrão, o OpenChamber só escuta na sua própria máquina (`127.0.0.1`). É preciso uma mudança deliberada para escutar mais amplamente, e você deve definir uma senha primeiro.
- Para os seus próprios dispositivos, prefira o [pareamento](/pt-br/connect-devices/) com o [Private Relay](/pt-br/private-relay/) — nada fica exposto publicamente.
- Se você precisa de uma URL pública, prefira um [túnel](/pt-br/tunnels/) ou uma rede privada (como uma VPN) a abrir uma porta para a internet.
- Se você colocar o OpenChamber atrás do seu próprio servidor HTTPS, veja [Reverse Proxy](/pt-br/reverse-proxy/).

## Modo empresarial

Se a sua equipe só pode enviar o conteúdo das conversas aos provedores de modelos que você configurou no OpenCode, ative o modo empresarial definindo uma variável de ambiente para o servidor do OpenChamber:

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

No app desktop, coloque-a no perfil do seu shell de login (por exemplo, `~/.zshrc`); o OpenChamber lê esse ambiente ao iniciar. Nada nas Configurações consegue desligar o modo. Com ele ativo:

- Os provedores de modelos vêm só da sua configuração do OpenCode. Conectar um provedor, entrar em um, adicionar uma chave ou criar um provedor personalizado fica desativado no OpenChamber; remover ou trocar contas que já existem continua funcionando. Isso só fecha a entrada pelo app; a trava em si é a política do OpenCode descrita abaixo.
- Os [Provedores de classificação (Jev)](/pt-br/classification-providers/) ficam desativados, inclusive um endpoint personalizado que alguém digite nas Configurações. A rede de segurança e o Auto não são oferecidos, e as sessões só vão para em andamento manualmente. Para usar o Jev pela sua própria infraestrutura, fixe um endpoint no servidor com `OPENCHAMBER_JEV_URL` (mais `OPENCHAMBER_JEV_MODEL` e, se ele precisar, `OPENCHAMBER_JEV_API_KEY`). Ele passa a ser o padrão, ainda dá para desativá-lo e nada mais pode ser escolhido.
- A leitura em voz alta pela OpenAI fica desativada. Um servidor próprio de fala ou de transcrição precisa rodar na mesma máquina. Vozes locais e modelos locais de ditado continuam funcionando.
- As notificações push para celulares e navegadores levam só um título genérico como "Agent response is ready", sem o texto da mensagem nem o nome da sessão. As notificações do desktop ficam na sua máquina e mantêm o texto completo.
- As verificações de atualização continuam rodando, então as correções de segurança ainda chegam até você, mas elas nunca reportam uso, nem mesmo o ID de instalação anônimo.
- Os [túneis externos](/pt-br/tunnels/) (Cloudflare, ngrok) ficam desativados. Um provedor de túnel descriptografa o tráfego na borda dele e vê cada requisição em texto puro.
- O [Private Relay](/pt-br/private-relay/) só funciona pelo seu próprio relay. Rode um [relay auto-hospedado](https://github.com/openchamber/openchamber-relay) e aponte o servidor para ele com `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws`. O relay compartilhado também não consegue ler o seu tráfego, já que é criptografado de ponta a ponta, mas o seu próprio mantém os metadados de conexão e a entrada para esta máquina dentro da sua rede. O pareamento de dispositivos na sua rede local continua funcionando.

As tarefas do modelo pequeno (títulos de sessão, resumos, mensagens de commit, o percurso de mudanças) não precisam de nenhum modo especial. Elas sempre rodam no modelo pequeno que você escolheu nas Configurações, em um modelo pequeno do provedor com que você está trabalhando ou no modelo padrão da sua configuração do OpenCode. Elas nunca recorrem a outro provedor que você por acaso tenha conectado.

Quais provedores de modelos podem ser usados é o OpenCode que decide, não o OpenChamber. Trave isso com as [políticas do OpenCode](https://opencode.ai/v2/docs/policies/): negue todos os provedores e depois permita os que você aprovou.

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "provider.use", "resource": "*", "effect": "deny" },
      { "action": "provider.use", "resource": "anthropic", "effect": "allow" }
    ]
  }
}
```

Um provedor negado desaparece mesmo que alguém adicione uma chave para ele. Coloque as políticas no arquivo global `~/.config/opencode/opencode.jsonc`, onde um projeto não consegue removê-las, ou distribua-as a partir de um workspace do OpenCode Console, que tem a palavra final. O modo empresarial cobre, além disso, o que o próprio OpenChamber envia.

As buscas na web e os acessos a páginas feitos pelo agente também passam pelo OpenCode, até o serviço de busca e até as próprias páginas. Se eles não devem sair da sua rede, negue-os com o mesmo tipo de política:

```jsonc
{ "action": "permission", "resource": "websearch:*", "effect": "deny" },
{ "action": "permission", "resource": "webfetch:*", "effect": "deny" }
```

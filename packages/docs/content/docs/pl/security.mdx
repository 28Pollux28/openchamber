# Bezpieczeństwo

OpenChamber daje dostęp do Twojej maszyny i Twojego kodu, więc zabezpiecz go, zanim ktokolwiek poza Tobą będzie mógł do niego dotrzeć. Ta strona omawia hasło UI, klucze dostępu (passkeys) oraz to, co warto wiedzieć przed udostępnieniem OpenChamber w sieci.

## Ustaw hasło UI

Uruchom OpenChamber z hasłem, a interfejs webowy poprosi o nie:

```bash
openchamber --ui-password be-creative-here
```

Możesz też ustawić je za pomocą zmiennej środowiskowej `OPENCHAMBER_UI_PASSWORD`, zamiast podawać je w wierszu poleceń. Po zalogowaniu OpenChamber zapamiętuje urządzenie na pewien czas, więc nie pyta za każdym razem.

Zawsze ustawiaj hasło, jeśli instancja jest dostępna dla kogokolwiek innego — zwłaszcza przez [tunel](/pl/tunnels/) lub publiczny internet.

## Klucze dostępu (passkeys)

Po ustawieniu hasła możesz dodać klucze dostępu (Face ID, Touch ID, klucz bezpieczeństwa) dla szybszego logowania. Dodaj je w **Settings → OpenChamber → Passkeys**.

Klucze dostępu są powiązane z bieżącym hasłem. Jeśli zmienisz lub usuniesz hasło, zapisane klucze dostępu zostaną wyczyszczone i będziesz je dodawać ponownie.

## Tokeny urządzeń

Urządzenia sparowane przez [Połącz urządzenie](/pl/connect-devices/) uwierzytelniają się własnymi tokenami per urządzenie, a nie hasłem UI. Linki parowania są jednorazowe i wygasają, jeśli nie zostaną użyte; każde sparowane urządzenie jest widoczne w **Settings → Remote Instances → Połącz z tym serwerem**, gdzie w każdej chwili możesz unieważnić dowolne z nich. Połączenia spoza domu przechodzą przez [Private Relay](/pl/private-relay/), który jest szyfrowany end-to-end i nie może odczytać Twojego ruchu.

## Zanim ją udostępnisz

- Domyślnie OpenChamber nasłuchuje tylko na Twojej własnej maszynie (`127.0.0.1`). Nasłuchiwanie szerzej wymaga celowej zmiany i najpierw powinieneś ustawić hasło.
- Dla własnych urządzeń preferuj [parowanie](/pl/connect-devices/) z [Private Relay](/pl/private-relay/) — nic nie jest wtedy wystawione publicznie.
- Jeśli potrzebujesz publicznego adresu URL, preferuj [tunel](/pl/tunnels/) lub sieć prywatną (jak VPN) zamiast otwierania portu do internetu.
- Jeśli umieszczasz OpenChamber za własnym serwerem HTTPS, zobacz [Reverse Proxy](/pl/reverse-proxy/).

## Tryb enterprise

Jeśli Twój zespół może wysyłać treść rozmów tylko do dostawców modeli skonfigurowanych w OpenCode, włącz tryb enterprise, ustawiając zmienną środowiskową dla serwera OpenChamber:

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

W aplikacji desktopowej wpisz ją do profilu powłoki logowania (na przykład `~/.zshrc`); OpenChamber odczytuje to środowisko przy starcie. W Ustawieniach nie da się tego trybu wyłączyć. Gdy jest włączony:

- Dostawcy modeli pochodzą wyłącznie z Twojej konfiguracji OpenCode. Podłączanie dostawcy, logowanie się do niego, dodawanie klucza i tworzenie własnego dostawcy są w OpenChamber wyłączone; usuwanie i przełączanie istniejących kont działa dalej. To zamyka tylko drogę przez aplikację; właściwą blokadą jest polityka OpenCode opisana niżej.
- [Dostawcy klasyfikacji (Jev)](/pl/classification-providers/) pozostają wyłączeni, łącznie z własnym endpointem wpisanym przez kogoś w Ustawieniach. Siatka bezpieczeństwa i Auto nie są oferowane, a sesje trafiają do toku tylko ręcznie. Aby korzystać z Jev przez własną infrastrukturę, przypnij endpoint na serwerze zmienną `OPENCHAMBER_JEV_URL` (plus `OPENCHAMBER_JEV_MODEL` i, jeśli jest potrzebny, `OPENCHAMBER_JEV_API_KEY`). Staje się on domyślny, nadal można go wyłączyć, a niczego innego nie da się wybrać.
- Odczytywanie na głos przez OpenAI jest wyłączone. Własny serwer syntezy mowy lub transkrypcji musi działać na tej samej maszynie. Lokalne głosy i lokalne modele dyktowania działają dalej.
- Powiadomienia push na telefony i do przeglądarek niosą tylko ogólny tytuł, taki jak "Agent response is ready", bez treści wiadomości i nazwy sesji. Powiadomienia na desktopie zostają na Twojej maszynie i zachowują pełny tekst.
- Sprawdzanie aktualizacji działa dalej, więc poprawki bezpieczeństwa nadal do Ciebie trafiają, ale nigdy nie raportuje użycia, nawet anonimowego identyfikatora instalacji.
- [Zewnętrzne tunele](/pl/tunnels/) (Cloudflare, ngrok) są wyłączone. Dostawca tunelu odszyfrowuje ruch na swoim brzegu sieci i widzi każde żądanie otwartym tekstem.
- [Private Relay](/pl/private-relay/) działa tylko przez Twój własny relay. Uruchom [self-hosted relay](https://github.com/openchamber/openchamber-relay) i wskaż go serwerowi przez `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws`. Wspólny relay też nie może odczytać Twojego ruchu, bo jest szyfrowany end-to-end, ale własny trzyma metadane połączeń i drogę do tej maszyny wewnątrz Twojej sieci. Parowanie urządzeń w sieci lokalnej działa dalej.

Zadania małego modelu (tytuły sesji, podsumowania, wiadomości commitów, omówienie zmian) nie wymagają żadnego specjalnego trybu. Zawsze działają na małym modelu wybranym w Ustawieniach, na małym modelu dostawcy, z którym akurat pracujesz, albo na domyślnym modelu z Twojej konfiguracji OpenCode. Nigdy nie przełączają się na innego dostawcę tylko dlatego, że akurat jest podłączony.

O tym, z jakich dostawców modeli w ogóle można korzystać, decyduje OpenCode, nie OpenChamber. Zablokuj to [politykami OpenCode](https://opencode.ai/v2/docs/policies/): zabroń wszystkich dostawców, a potem zezwól na zatwierdzonych.

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "provider.use", "resource": "*", "effect": "deny" },
      { "action": "provider.use", "resource": "anthropic", "effect": "allow" }
    ]
  }
}
```

Zabroniony dostawca znika, nawet jeśli ktoś doda do niego klucz. Umieść polityki w globalnym `~/.config/opencode/opencode.jsonc`, gdzie projekt nie może ich znieść, albo dostarczaj je z workspace’u OpenCode Console, który ma ostatnie słowo. Tryb enterprise obejmuje ponad to, co wysyła sam OpenChamber.

Wyszukiwania w sieci i pobieranie stron przez agenta też idą przez OpenCode, do usługi wyszukiwania i do samych stron. Jeśli nie powinny wychodzić poza Twoją sieć, zabroń ich tym samym rodzajem polityki:

```jsonc
{ "action": "permission", "resource": "websearch:*", "effect": "deny" },
{ "action": "permission", "resource": "webfetch:*", "effect": "deny" }
```

## Powiązane

- [Połącz urządzenie](/pl/connect-devices/) — jednorazowe parowanie i tokeny per urządzenie
- [Private Relay](/pl/private-relay/) — szyfrowany end-to-end dostęp z dowolnego miejsca
- [Tunele](/pl/tunnels/) — udostępnij publiczny URL, gdy go potrzebujesz
- [Reverse Proxy](/pl/reverse-proxy/) — uruchom OpenChamber za własnym serwerem

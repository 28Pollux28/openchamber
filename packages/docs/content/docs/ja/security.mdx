# セキュリティ

OpenChamber はあなたのマシンとコードへのアクセスを提供するため、あなた以外が到達できるようにする前に必ず保護してください。このページでは UI パスワード、パスキー、ネットワークに OpenChamber を公開する前に知っておくべきことを説明します。

## UI パスワードを設定する

パスワード付きで OpenChamber を起動すると、ブラウザ UI がそれを要求します。

```bash
openchamber --ui-password be-creative-here
```

コマンドラインに書く代わりに、`OPENCHAMBER_UI_PASSWORD` 環境変数で設定することもできます。サインイン後、OpenChamber はしばらくそのデバイスを記憶するため、毎回求められることはありません。

インスタンスが自分以外から到達可能な場合は、必ずパスワードを設定してください。特に [トンネル](/tunnels/) や public internet 経由の場合は重要です。

## パスキー

パスワードを設定すると、より速くサインインするためにパスキー（Face ID、Touch ID、セキュリティキー）を追加できます。**Settings → OpenChamber → Passkeys** で追加します。

パスキーは現在のパスワードに紐づきます。パスワードを変更または削除すると、保存済みパスキーは消去され、再追加が必要になります。

## デバイストークン

[デバイスを接続する](/connect-devices/) でペアリングしたデバイスは、UI パスワードではなく、デバイスごとの専用トークンで認証します。ペアリングリンクは 1 回限りで、未使用なら期限切れになります。ペアリング済みのデバイスはすべて **Settings → Remote Instances → このサーバーに接続** に一覧表示され、いつでも無効化できます。外出先からの接続は [Private Relay](/private-relay/) を経由します。リレーはエンドツーエンドで暗号化されており、通信内容を読むことはできません。

## 公開する前に

- デフォルトでは、OpenChamber はあなたのマシン上（`127.0.0.1`）でのみ待ち受けます。より広く待ち受けるには明示的な変更が必要で、その前にパスワードを設定するべきです。
- 自分のデバイスなら、[Private Relay](/private-relay/) を使った [ペアリング](/connect-devices/) を推奨します。何も公開されません。
- 公開 URL が必要な場合は、インターネットにポートを開けるより、[トンネル](/tunnels/) または VPN のようなプライベートネットワークを推奨します。
- OpenChamber を自分の HTTPS サーバーの背後に置く場合は、[リバースプロキシ](/reverse-proxy/) を参照してください。

## エンタープライズモード

チームが会話の内容を OpenCode で設定したモデルプロバイダーにしか送れない場合は、OpenChamber サーバーに環境変数を設定してエンタープライズモードをオンにします。

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

デスクトップアプリでは、ログインシェルのプロファイル（例：`~/.zshrc`）に書きます。OpenChamber は起動時にその環境を読み込みます。設定からこのモードをオフにすることはできません。オンのときは次のようになります。

- モデルプロバイダーは OpenCode の設定からのみ読み込まれます。OpenChamber でプロバイダーを接続する、サインインする、キーを追加する、カスタムプロバイダーを作成する操作はオフになります。すでにあるアカウントの削除や切り替えは引き続きできます。これはアプリ経由の入り口を閉じるだけで、実際のロックは後述の OpenCode ポリシーです。
- [分類プロバイダー（Jev）](/classification-providers/)はオフのままで、誰かが設定で入力したカスタムエンドポイントも同様です。セーフティネットと Auto は表示されず、セッションは手動で移したときだけ作業中になります。自社のインフラ経由で Jev を使うには、サーバー側で `OPENCHAMBER_JEV_URL`（加えて `OPENCHAMBER_JEV_MODEL`、必要なら `OPENCHAMBER_JEV_API_KEY`）を設定してエンドポイントを固定します。それが既定になり、オフにはできますが、ほかのものは選べません。
- OpenAI による読み上げはオフになります。カスタムの音声合成サーバーや文字起こしサーバーは、同じマシン上で動かす必要があります。ローカルの音声とローカルの音声入力モデルはそのまま使えます。
- スマートフォンやブラウザへのプッシュ通知には「Agent response is ready」のような汎用のタイトルだけが入り、メッセージ本文やセッション名は含まれません。デスクトップ通知はあなたのマシンの中にとどまり、全文を表示します。
- 更新の確認は引き続き行われるため、セキュリティ修正は届きます。ただし利用状況は一切報告せず、匿名のインストール ID すら送りません。
- [外部トンネル](/tunnels/)（Cloudflare、ngrok）はオフになります。トンネルのプロバイダーはエッジで通信を復号するため、すべてのリクエストを平文で見られます。
- [Private Relay](/private-relay/) は自前のリレー経由でのみ動作します。[セルフホストのリレー](https://github.com/openchamber/openchamber-relay)を動かし、`OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws` でサーバーをそこに向けてください。共有リレーもエンドツーエンドで暗号化されているため通信内容は読めませんが、自前のリレーなら接続のメタデータとこのマシンへの入り口をネットワーク内にとどめられます。ローカルネットワーク上でのデバイスのペアリングは引き続き使えます。

小さなモデルのタスク（セッションのタイトル、要約、コミットメッセージ、変更のウォークスルー）に特別なモードは必要ありません。常に、設定で選んだ小さなモデル、作業中のプロバイダーの小さなモデル、または OpenCode の設定にあるデフォルトモデルのいずれかで動きます。たまたま接続している別のプロバイダーに切り替わることはありません。

そもそもどのモデルプロバイダーを使えるかを決めるのは、OpenChamber ではなく OpenCode です。[OpenCode ポリシー](https://opencode.ai/v2/docs/policies/)で固定してください。すべてのプロバイダーを拒否し、そのうえで承認したものを許可します。

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "provider.use", "resource": "*", "effect": "deny" },
      { "action": "provider.use", "resource": "anthropic", "effect": "allow" }
    ]
  }
}
```

拒否されたプロバイダーは、誰かがキーを追加しても表示されません。ポリシーは、プロジェクトから解除できないグローバルの `~/.config/opencode/opencode.jsonc` に置くか、最終的な決定権を持つ OpenCode Console のワークスペースから配布してください。エンタープライズモードが扱うのは、それに加えて OpenChamber 自身が送るものです。

エージェントの Web 検索やページ取得も OpenCode を経由し、検索サービスやページそのものに接続します。これらをネットワークの外に出したくない場合は、同じ種類のポリシーで拒否してください。

```jsonc
{ "action": "permission", "resource": "websearch:*", "effect": "deny" },
{ "action": "permission", "resource": "webfetch:*", "effect": "deny" }
```

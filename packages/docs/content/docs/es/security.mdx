# Seguridad

OpenChamber da acceso a tu máquina y a tu código, así que bloquéalo antes de que nadie más que tú pueda alcanzarlo. Esta página cubre la contraseña de UI, las passkeys y lo que debes saber antes de exponer OpenChamber a una red.

## Define una contraseña de UI

Inicia OpenChamber con una contraseña y la UI del navegador la pedirá:

```bash
openchamber --ui-password be-creative-here
```

También puedes definirla con la variable de entorno `OPENCHAMBER_UI_PASSWORD` en lugar de ponerla en la línea de comandos. Tras iniciar sesión, OpenChamber recuerda el dispositivo durante un tiempo para no pedírtela cada vez.

Define siempre una contraseña si la instancia es accesible para alguien más, especialmente a través de un [túnel](/es/tunnels/) o de internet público.

## Passkeys

Una vez definida una contraseña, puedes añadir passkeys (Face ID, Touch ID, una llave de seguridad) para un inicio de sesión más rápido. Añádelas en **Settings → OpenChamber → Passkeys**.

Las passkeys están vinculadas a la contraseña actual. Si cambias o eliminas la contraseña, las passkeys guardadas se borran y tendrás que añadirlas de nuevo.

## Tokens de dispositivo

Los dispositivos vinculados mediante [Conectar un dispositivo](/es/connect-devices/) se autentican con sus propios tokens por dispositivo, no con la contraseña de UI. Los enlaces de vinculación son de un solo uso y caducan si no se usan; cada dispositivo vinculado aparece en **Settings → Remote Instances → Conectarse a este servidor**, donde puedes revocar cualquiera en cualquier momento. Las conexiones fuera de casa pasan por el [Private Relay](/es/private-relay/), que está cifrado de extremo a extremo y no puede leer tu tráfico.

## Antes de exponerlo

- De forma predeterminada, OpenChamber solo escucha en tu propia máquina (`127.0.0.1`). Hace falta un cambio deliberado para escuchar más ampliamente, y deberías definir una contraseña primero.
- Para tus propios dispositivos, prefiere la [vinculación](/es/connect-devices/) con el [Private Relay](/es/private-relay/): no se expone nada públicamente.
- Si necesitas una URL pública, prefiere un [túnel](/es/tunnels/) o una red privada (como una VPN) antes que abrir un puerto a internet.
- Si pones OpenChamber detrás de tu propio servidor HTTPS, consulta [Proxy inverso](/es/reverse-proxy/).

## Modo empresa

Si tu equipo solo puede enviar el contenido de las conversaciones a los proveedores de modelos que configuraste en OpenCode, activa el modo empresa definiendo una variable de entorno para el servidor de OpenChamber:

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

Para la app de escritorio, ponla en el perfil de tu shell de inicio de sesión (por ejemplo, `~/.zshrc`); OpenChamber lee ese entorno al arrancar. Nada en Configuración puede desactivar el modo. Con él activado:

- Los proveedores de modelos salen solo de tu configuración de OpenCode. Conectar un proveedor, iniciar sesión en uno, añadir una clave o crear un proveedor personalizado está desactivado en OpenChamber; quitar o cambiar las cuentas que ya existen sigue funcionando. Esto solo cierra la entrada a través de la app; el bloqueo en sí es la política de OpenCode que se describe más abajo.
- Los [Proveedores de clasificación (Jev)](/es/classification-providers/) se quedan desactivados, incluido un endpoint personalizado que alguien escriba en Configuración. La red de seguridad y Auto no se ofrecen, y las sesiones solo pasan a en curso a mano. Para usar Jev a través de tu propia infraestructura, fija un endpoint en el servidor con `OPENCHAMBER_JEV_URL` (más `OPENCHAMBER_JEV_MODEL` y, si lo necesita, `OPENCHAMBER_JEV_API_KEY`). Pasa a ser el predeterminado, se puede seguir desactivando y no se puede elegir nada más.
- La lectura en voz alta a través de OpenAI está desactivada. Un servidor propio de voz o de transcripción tiene que ejecutarse en la misma máquina. Las voces locales y los modelos de dictado locales siguen funcionando.
- Las notificaciones push a teléfonos y navegadores solo llevan un título genérico como "Agent response is ready", sin el texto del mensaje ni el nombre de la sesión. Las notificaciones de escritorio se quedan en tu máquina y conservan el texto completo.
- Las comprobaciones de actualizaciones siguen funcionando, así que las correcciones de seguridad te siguen llegando, pero nunca informan del uso, ni siquiera del ID de instalación anónimo.
- Los [túneles externos](/es/tunnels/) (Cloudflare, ngrok) están desactivados. Un proveedor de túneles descifra el tráfico en su borde y ve cada solicitud en texto plano.
- El [Private Relay](/es/private-relay/) solo funciona a través de tu propio relay. Ejecuta un [relay autoalojado](https://github.com/openchamber/openchamber-relay) y apunta el servidor hacia él con `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws`. El relay compartido tampoco puede leer tu tráfico, ya que está cifrado de extremo a extremo, pero el tuyo mantiene los metadatos de conexión y la entrada a esta máquina dentro de tu red. La vinculación de dispositivos en tu red local sigue funcionando.

Las tareas del modelo pequeño (títulos de sesión, resúmenes, mensajes de commit, el recorrido de cambios) no necesitan ningún modo especial. Siempre se ejecutan con el modelo pequeño que elegiste en Configuración, con un modelo pequeño del proveedor con el que estás trabajando o con el modelo predeterminado de tu configuración de OpenCode. Nunca recurren a otro proveedor que simplemente tengas conectado.

Qué proveedores de modelos se pueden usar lo decide OpenCode, no OpenChamber. Fíjalo con las [políticas de OpenCode](https://opencode.ai/v2/docs/policies/): deniega todos los proveedores y luego permite los que aprobaste.

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "provider.use", "resource": "*", "effect": "deny" },
      { "action": "provider.use", "resource": "anthropic", "effect": "allow" }
    ]
  }
}
```

Un proveedor denegado desaparece aunque alguien añada una clave para él. Pon las políticas en el archivo global `~/.config/opencode/opencode.jsonc`, donde un proyecto no puede levantarlas, o entrégalas desde un espacio de trabajo de OpenCode Console, que tiene la última palabra. El modo empresa cubre además lo que envía el propio OpenChamber.

Las búsquedas web y las descargas de páginas del agente también pasan por OpenCode, hacia el servicio de búsqueda y hacia las propias páginas. Si no deben salir de tu red, deniégalas con el mismo tipo de política:

```jsonc
{ "action": "permission", "resource": "websearch:*", "effect": "deny" },
{ "action": "permission", "resource": "webfetch:*", "effect": "deny" }
```
